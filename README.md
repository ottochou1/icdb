# 华政选课 · PHP + MySQL 部署版

给华东政法大学同学用的选课参考站：课程信息共建 + 豆瓣式评分短评 + 课程讨论 + 「友邻」闲聊板块。注册并通过在读认证后才能互动，添加课程还需管理员单独授权。

这是**虚拟主机部署用的生产主线**（PHP + MySQL）。仓库根目录下还有一份早期 Node.js 版本，仅用于本地快速预览，功能少于本版本。

## 环境要求

- PHP **7.4+**（推荐 8.0 / 8.1 / 8.2）
- 扩展：`pdo_mysql`、`mbstring`（绝大多数虚拟主机默认开启）
- MySQL 5.6+ / MariaDB 10.1+（需支持 utf8mb4 与 InnoDB 外键）
- 无需任何 composer 依赖、无需 URL 重写（rewrite）

## 本地运行（Windows，一键启停）

仓库根目录带了两个脚本，双击即可：

- **`start.bat`** — 启动 MariaDB（未运行则自动拉起）→ 启动 PHP 内置服务器（端口 **8081**）→ 自动打开浏览器。第一次运行若没有 `config.php`，会自动打开安装向导。
- **`stop.bat`** — 停止 PHP 服务器 + 优雅关闭数据库（`mysqladmin shutdown`，不会损坏数据）。

访问地址：**http://127.0.0.1:8081/index.php**。首次安装后请注册自己的账号；如导入本地演示数据，请按部署环境单独保存演示凭据，不要提交到公共仓库。

脚本顶部的两个变量按你的实际安装路径调整：

```
set PHP=C:\Users\...\php.exe          PHP 可执行文件
set MYSQLBIN=C:\Program Files\MariaDB 13.0\bin   数据库 bin 目录
```

启动后会在 `logs/` 下生成 `php.log`、`mysql.log`，排错看这两个文件。
运行期间请保留那个黑色命令行窗口；关掉窗口不会立刻结束服务，要彻底停止请用 `stop.bat`。

> 注意：`.bat` 文件必须是 **CRLF 换行**。用某些编辑器保存成 LF 会导致 cmd 解析错乱（表现为脚本似乎没执行、无任何输出）。

## 部署步骤

1. 在虚拟主机面板里创建一个 **MySQL 数据库**（记下库名、用户名、密码；字符集选 utf8mb4）。
2. 用 FTP 把 `php/public/` 目录里的**所有文件和目录**上传到站点根目录（`public_html` / `wwwroot` / `htdocs`，名字因主机而异）。上传后根目录应该能看到 `index.php`、`api.php`、`install.php`、`assets/`。
3. 浏览器访问 `http://你的域名/install.php`，填写数据库信息 + **管理员账号** → 点「开始安装」。
   - 程序会自动建 13 张表、写入 `config.php`，可选导入演示数据。
   - **管理员账号必填**：不导入演示数据时它是库里唯一的账号，而「设为管理员」按钮只有管理员能点 —— 不填将永远进不去后台。
   - 如果主机禁止自动建库，先用面板建好库再安装即可。
4. 安装完成后**删除 `install.php`**（程序也会生成 `install.lock` 防止被重复执行；如需重装，删掉 `install.lock` 和 `config.php` 再来一次）。
5. 访问 `http://你的域名/`，用管理员邮箱登录即可在右上角进入管理后台。

> **VPS 用户（1核1GB 宝塔 LNMP）请改用 `deploy/DEPLOY.md`**，那里有完整的一步步操作、
> 内存调优、Nginx 加固与上线自检清单，本节的虚拟主机流程不适用。

> 演示数据里的教师姓名与评价均为虚构，正式开放前建议在后台清空（或用 `TRUNCATE` 清表），让同学录入真实课程。

## 学生认证与权限机制

新用户注册后**只能浏览和搜索**（课程、短评、帖子都能看），要参与互动必须先通过在读认证：

1. 注册成功后系统会发一条站内信，内含认证页链接（`#/verify`）；也可以点右上角「去认证」。
2. 认证页上传学生证 / 校园卡 / 在读证明，**仅支持 PDF 和图片（jpg / png / gif / webp），单个文件不超过 10MB**。
3. 管理员在「管理后台 → 认证审核」中查看材料并作出决定：
   - **通过**：立即授予发帖 / 评分 / 评论 / 点赞 / 私信权限，并加上「在读认证」标识；
   - **驳回**：填写原因（会通过站内信告知），用户可重新提交。
4. **无论通过还是驳回，证明材料都会在审核完成时立刻从服务器删除**。数据库只保留文件名、格式、大小、提交与处理时间、处理人，不保存证件文件本身。
5. 管理员账号自动豁免，无需认证。
6. **在读认证不等于课程上传权限**：普通用户即使已认证，也不能添加或批量导入课程；管理员需在「用户管理」中单独点击“授予上传权限”。管理员始终拥有课程上传权限。

被封禁的用户仍可浏览，但无法发言。

## 管理后台

管理员登录后右上角出现「管理后台」入口（`#/admin`），七个模块：

- **认证审核**：按待审核 / 已通过 / 未通过筛选，查看证明材料、通过或驳回。
- **用户管理**：搜索用户，设置或取消管理员、手动标记认证、授予 / 收回课程上传权限、封禁 / 解封。
- **内容管理**：按关键词搜索帖子与短评并删除，删除后会站内信通知作者。
- **课程管理**：搜索 / 筛选 / 排序全部课程，就地修改课名、教师、课程代码、学分、类别、开课部门、考核方式、授课语言与简介；删除课程；把重名重复课**合并**到另一门课（短评、讨论与课程代码一并转移）。详见下方「后台课程管理」。
- 课程检索页与后台课程管理的**类别 / 开课部门下拉栏选项都来自课程表真实取值**（各选项附课程数），不会出现"下拉里有、库里没有"导致筛选结果为空的情况。
- **课程导入**：通用批量导入（自定表头），详见下方「后台批量导入课程」。
- **教务表格导入**：专用于教务处开课查询导出的 11 列表格，详见「教务表格导入」。
- **站点设置**：开启 / 关闭闭站维护。开启后非管理员会被引导到登录页，普通账号无法登录或调用业务接口，管理员仍可进入站点和后台。

第一个注册的用户自动成为管理员。要把已有账号设为管理员，可执行：

```sql
UPDATE hz_users SET is_admin = 1, verified = 1 WHERE email = '你的邮箱';
```

### 后台课程管理

管理后台 → 课程管理（`admin.courses` / `admin.course.update` / `admin.course.delete` / `admin.course.merge`）：

- 列表可按课名 / 教师 / 课程代码 / 开课部门搜索，按类别与开课部门筛选，按最新添加 / 最近修改 / 短评数 / 评分 / 名称排序，每页 20 条。
- 点「编辑」就地展开表单，改完保存；留空表示清空该字段（课程名至少 2 个字，教师不能为空）。
- **课程代码**可填多个，用顿号 / 逗号 / 分号分隔，第一个作为主代码写回 `courses.code`，其余存进 `course_codes`，任一代码都能被搜到。
- 点「删除」会连带删掉该课下的短评与讨论（确认弹窗会显示数量），并站内信通知建课人；**重名重复课请改用「合并到…」**，否则评分会一起丢掉。
- 「合并到…」：搜到目标课程 → 确认 → 来源课程的短评、讨论帖、课程代码并入目标课程，再删除来源课程。同一位同学在两门课都评过分的，保留目标课程那条，来源那条会被丢弃（提示里会给出丢弃条数）。

### 后台批量导入课程

管理后台 → 课程导入（`admin.courses.import`）。比前台的导入更强，适合一次性灌入整份培养方案：

- **支持 Excel**：可直接上传 `.xlsx`，不用先另存为 CSV；`.csv` / `.txt` 和直接粘贴表格也可以。
- **预演模式**：点「预演」只解析不写入，先看清会新增几条、更新几条、跳过几条，确认后再点「确认导入」。
- **两种去重策略**：
  - *跳过*（默认）—— 同名同老师的课程不作改动，最安全。
  - *更新* —— 用表格里的学分 / 开课学院 / 课程类别 / 简介覆盖已有课程；**表格里留空的字段保持原值**，不会被清空。
- **编码自动处理**：Excel 在中文 Windows 下另存的 CSV 通常是 GBK，系统会自动识别转码，不会乱码。
- **无效行可见**：课程名为空的行不会被静默丢弃，会列进「跳过的课程」并标明原因。
- **限制**：单次最多 2000 行，文件不超过 10MB。

表头支持「课程名称 / 老师 / 课程代码 / 学分 / 开课学院 / 课程类别 / 课程简介」，顺序不限；没有表头时按这个顺序读列。页面上有「下载模板」和「导出全部课程」两个按钮。

> xlsx 解析不依赖服务器的 php-zip 扩展（用 zlib 直接读取 zip 包），虚拟主机没装 zip 也能正常导入 Excel。

### 教务表格导入

管理后台 → 教务表格导入（`admin.edu.import`）。针对教务处开课查询导出的固定 11 列表格：

| 列 | 课程代码 | 课程名称 | 学分 | 课程序号 | 教学班 | 课程类别 | 开课部门 | 授课教师 | 日期时间地点人员 | 考核方式 | 授课语言 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 处理 | 取 | 取 | 取 | 忽略 | 忽略 | 取 | 取 | 取 | 忽略 | 取 | 取 |

处理规则：

1. **教师姓名清洗**：去掉「（主讲）」这类括号标记，只保留姓名。一格写了多位老师（如 `张三（主讲）、李四`）会逐个清洗后用顿号连接。
2. **按下述规则合并**：**课程名称 + 授课教师 相同**的多行（通常是不同教学班 / 不同课程序号）合并为一门课，不会重复建课。
3. **课程代码全部保留**：合并后所有不同的课程代码都存下来，课程页全部展示，**用其中任何一个代码搜索都能命中**。
4. 学分、课程类别、开课部门、考核方式、授课语言取组内第一个非空值；同名不同老师（如民法学由张三、李四分别开）仍然是两门独立课程。

同样支持 .csv / .txt / .xlsx、预演模式、skip / update 两种去重策略、GBK 自动转码。预演结果里会显示「表头识别结果」，一眼看出哪些列被读取、哪些被忽略。

导入后，课程详情页（打分页面）会展示：多个课程代码、任课老师、学分、课程类别、开课部门、考核方式、授课语言。

> 数据结构：课程表新增 `exam_mode`（考核方式）和 `language`（授课语言）两个字段，另建 `course_codes` 表存一门课的多个代码（随课程删除级联清理）。

## 线上更新（热更新，不需要停站）

### 先说结论：PHP 天然就是热的

PHP 是解释执行的，没有编译产物，也没有常驻内存的应用进程。你把新文件覆盖上去，下一个请求用的就是新代码——**不需要重启、不需要停站、不存在"热更新"这个技术难题**。

真正需要额外处理的只有三件事，处理完就是完整的发布流程：

| 要处理的点 | 说明 | 谁来做 |
| --- | --- | --- |
| **OPcache** | 宝塔 / LNMP 默认开启 PHP OPcache，会把编译后的脚本缓存在内存里。默认配置下最多 2 秒就会自动发现文件变化，但保险起见发布后要 reload 一次 PHP-FPM | `publish.sh` 自动做 |
| **数据库结构** | 新版本可能加了字段或表。每次发布都跑一次 `php upgrade.php`，它是**幂等**的，结构已最新时全部显示"已存在，跳过"，可以放心反复执行 | `publish.sh` 自动做 |
| **前端缓存** | 浏览器 / CDN 缓存了旧 JS，用户看到的就是旧页面。这是最容易踩的坑，见下 | 已内置版本戳 + Nginx 配置 |

### 前端缓存：本站已经帮你处理好了

- `index.php` 输出的 `style.css` 和 `app.js` 都带了 `?v=xxxx` 版本戳。默认取 `assets/` 目录下所有文件的最新修改时间，**上传即变**；也可以在 `config.php` 里写死 `'asset_version' => '20261029'` 由你手工控制。
- `deploy/nginx-site.conf` 里把 `/assets/` 下的 js、css 配成了 `Cache-Control: no-cache`（协商缓存，没变只回一个 304，开销可忽略）。

> **如果你自己配 Nginx，绝对不要给 js / css 设 `expires 7d` 或 `immutable`**。否则你改完代码上传，用户七天里拿的还是旧文件，表现就是"功能明明上线了，页面却没变化甚至报错"。
>
> 注意 ES Module 的子模块（`assets/js/views/*.js`）是由 `app.js` 里的 `import` 加载的，URL 上不带版本戳，所以**必须**靠协商缓存保证它们也能更新——只加 `?v=` 是不够的，两件事要一起做。

### 绝不能被覆盖的三样东西

| 文件 | 为什么 |
| --- | --- |
| `config.php` | 存着服务器上的数据库账号密码；被本地的覆盖掉，站点立刻 500 |
| `install.lock` | 存在即表示已安装；丢了会重新进入安装向导 |
| `uploads/` | 里面可能有**还没审核的学生证明材料**，覆盖或删除等于丢失隐私材料 |

`publish.sh` 会自动排除这三项；如果你用 FTP 手动上传，请务必别勾选这几个。

### 标准发布流程（有 SSH，推荐）

```bash
# ① 开发机打包（在 php/public 目录里执行，只打站点内容）
cd php/public
tar -czf ~/hz-$(date +%Y%m%d-%H%M).tar.gz \
    --exclude=config.php --exclude=install.lock --exclude=uploads --exclude=.deploy .

# ② 上传到服务器
scp ~/hz-20261029-1830.tar.gz root@你的服务器:/root/

# ③ 服务器上执行一键发布（站点根目录 + 域名，域名用于最后的冒烟检查）
ssh root@你的服务器
bash /path/to/deploy/publish.sh /root/hz-20261029-1830.tar.gz \
     /www/wwwroot/course.example.com course.example.com
```

`publish.sh` 会依次做：备份当前版本 → 解压 → 覆盖（跳过上面三个文件）→ 跑 `upgrade.php` → reload PHP-FPM 与 Nginx → 冒烟检查 → 打印回滚命令。备份放在站点根的 `.deploy/backups/<时间戳>/`，自动保留最近 10 份。

### 一键回滚

```bash
bash deploy/rollback.sh                    # 列出可用备份，并回滚到最新一个
bash deploy/rollback.sh 20261029-1830      # 回滚到指定备份
```

只还原代码文件，**不动 `config.php` 和 `uploads/`**，所以回滚后不用重新配数据库，也不会丢学生的认证材料。注意回滚不还原数据库结构——如果本次更新改过表结构，请确认旧代码能兼容当前结构。

### 只有虚拟主机 / FTP（没有 SSH）

1. 本地打包同上，用 FTP 覆盖上传并解压，**手动确认没有覆盖** `config.php`、`install.lock`、`uploads/`。
2. 数据库升级：本站的 Nginx 配置默认只放行 `index.php` 和 `api.php`，`upgrade.php` 会被 404。要么临时把它加进放行列表、用管理员账号登录后在浏览器访问 `/upgrade.php`，跑完再删掉；要么用主机商提供的"计划任务 / 命令行"执行 `php upgrade.php`。
3. 确认 OPcache：虚拟主机一般没法 reload PHP-FPM，但默认配置下 2 秒内会自动生效，等一下刷新即可。若主机商强制开启且 `validate_timestamps=0`，只能联系客服或等缓存过期。
4. 前端缓存同上，已由版本戳处理；如果站点前面套了 CDN（如 Cloudflare），记得在 CDN 后台"清除缓存"。

### 关于"零中断"

严格意义上的原子发布是"版本目录 + 软链接瞬时切换"（`releases/20261029` → `current`），切换在毫秒级完成，不存在上传中途的不一致窗口。本站按推荐配置打包只有约 80KB，上传覆盖只需一两秒，这个窗口极小，所以用简单的"备份 + 覆盖"方案即可，换来的是**不做目录切换、不受 `open_basedir` 限制、回滚更直观**。

如果你确实要做到零窗口（比如以后站点变大、有持续流量），可以改成：`/www/wwwroot/site` 作为软链接指向 `/www/wwwroot/releases/<版本>`，上传完整版本目录后 `ln -sfn` 切换。注意宝塔默认给站点设了 `open_basedir`，要把 releases 目录也加进去，并在切换后 reload PHP-FPM（否则 OPcache 仍按旧 realpath 取代码）。

### 附：首次从旧版本升级

1. 上传新版本文件，**保留** `config.php`、`install.lock` 和 `uploads/`。
2. 命令行执行 `php upgrade.php`，或以管理员身份登录后在浏览器访问 `/upgrade.php`。
3. 升级会给用户表加认证、封禁和 `can_upload_courses` 字段，建新表（包括 `settings` / `verifications` / `notifications` / `conversations` / `messages` / `course_codes`），给课程表加 `exam_mode`、`language`，并把已有管理员标记为已认证。旧普通账号的课程上传权限默认关闭，需要管理员逐个授权。
4. 升级脚本幂等，可重复执行；已有课程的课程代码会自动迁移进 `course_codes` 表。
5. 升级完成后删除 `upgrade.php`。

## 运行要求补充（认证上传）

认证材料上限 10MB，PHP 侧必须放行，否则文件会在到达程序前就被拒绝：

```ini
upload_max_filesize = 12M
post_max_size = 14M
```

虚拟主机一般在面板「PHP 设置」里改，或者联系主机商调整。上传目录 `uploads/verify/` 已放置 `.htaccess` 禁止直接访问（Nginx 主机请自行加一条 `location ^~ /uploads/verify/ { deny all; }`）。

## 运维建议

- **备份**：定期 `mysqldump -u 用户 -p 数据库 > backup.sql`，或只导出 13 张 `hz_` 前缀的表。
- **表前缀**：同一数据库放多个站点时，安装时改表前缀（默认 `hz_`）。
- **会话清理**：`DELETE FROM hz_sessions WHERE expires_at < UNIX_TIMESTAMP()*1000;` 可定期执行。
- **HTTPS**：站点启用 HTTPS 后，Cookie 会自动带 `Secure` 属性。
- **删表重装**：删除 13 张 `hz_` 表 + `config.php` + `install.lock` 后重跑 `install.php`。
- 如主机把日志写在站点目录（如 `php_errors.log`），记得定期清理或把 `error_log` 指到目录外。
